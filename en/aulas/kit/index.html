Lesson 1 · 15 min

The kit: seven files that hold a long run together

A long session fails in three ways: it doesn't know when to stop, it forgets what it did after compaction, and it spends what it shouldn't. The execucao-longa kit answers with files, not with the model's memory: the agent rereads the folder instead of remembering. In this lesson you install the kit and create your first folder.

Goal: create the longrun/ folder for a run and say, for each of the seven files, who writes it, when it is read, and whether it only appends.

Scroll the page: each step below lights up its part of the diagram.

  1. 1/6

    goal.md

    Result in one sentence, done criteria (function, regression, limit), caps, constraints, and human gates. It is the only file the agent should not rewrite: changing the goal midway means changing the task.

  2. 2/6

    plan.md + state.md

    Both are snapshots of right now: rewrite, don't accumulate. state.md ends with the exact commands to resume. When the first line of "Funciona" says concluído, the watchdog and the hook stop treating the run as active.

  3. 3/6

    progress, failures, decisions

    Dated history in a table. You never delete a line: it's what lets you see later whether the agent reopened an item that was already done or repeated the same attempt three times.

  4. 4/6

    canal.md

    Project knowledge, not task state: where things are, the right name for each piece, the trap that cost an hour. Append only, one line per fact, with a date. The hook asks you to fill it in at band 1 (lesson 3).

  5. 5/6

    Agent or loop

    After every compaction or resume, the first thing is to reread the files, in this order: goal → state → plan → canal → end of progress and failures, and continue from the first pending item.

  6. 6/6

    The folder is the memory

    The goal stays parked in goal.md; the now lives in plan and state; the history only grows in progress, failures and decisions; what the summary loses lives in the canal.

The same files work for Claude Code and for Codex: one picks up what the other wrote.

02 · When each file comes into play

One run from start to finish, seen through the files.

1. Before

novo-longrun.sh creates the folder with the seven files already stamped with the date.

You fill in goal.md. It's the slow part, and it decides whether the run finishes (lesson 2).

Folder namelongrun/2026-10-19-contador-palavras/

2. Every cycle

Reads state and plan, picks the next useful action, runs it and tests it.

At the end it rewrites state and plan and adds a line to progress. If something went wrong, a line in failures.

A progress.md line| 2026-10-01 14:30 | medição do piloto | 7714c3c | sim (nível 3) | 332791 / 304000 / 4296 | 0 |

3. After compacting

The compaction summary mixes what is confirmed with guesses. The files don't.

The agent rereads goal → state → plan → canal before acting and does not reopen what state says is done.

4. At the end

state.md says done, but you are the one who closes it: run the final test yourself and measure the session (lesson 7).

The smallest fix for each failure goes from failures.md to the project's FALHAS.md.

## Execução longa (/goal, loop, objetivo de horas) — método em ~/projetos/execucao-longa

- **Antes de começar:** `~/projetos/execucao-longa/tools/novo-longrun.sh <projeto> <slug>` cria `longrun/<data>-<slug>/` (goal, plan, state, progress, failures, decisions, canal). Critério de pronto no `goal.md` em **nível 3+**: `comando → saída esperada`, cobrindo função, regressão e limite, sem atalho possível (contagem mínima, testes congelados, validador).
- **Durante:** releia goal → state → plan → canal após toda compactação ou retomada; registre cedo no `canal.md` (só acrescentar) fatos, aprendizados, glossário e armadilhas; teste cada mudança; commit a cada checkpoint; continue enquanto houver próxima ação útil e segura.
- **Parar e chamar o humano:** 3 ciclos sem avanço mensurável; o mesmo plano de fechamento repetido sem fechar ou item já feito reaberto (contexto degradou); crédito/API, ação irreversível ou externa, credencial ausente, decisão de negócio.
- **Faixas de contexto** (no Claude Code o hook avisa uma vez cada; no Codex, acompanhe o % em `/status`): ~50% → registrar no `canal.md`; ~70% → atualizar estado e pedir `/compact`; ~85% ou 3ª compactação → `/session-handoff` + sessão nova + `/prime`.
- **Headless:** `~/projetos/execucao-longa/tools/loop-longrun.sh <pasta-longrun>` (flock, timeout, MemoryMax, testes protegidos, parada por estagnação). Medir: `tools/medir-sessao.py <jsonl>`.
- Tetos sempre: timeout, memória (`systemd-run --user --scope -p MemoryMax=`), saída de ferramenta curta.
- **Histórico:** `recall "termo" [--projeto X] [--fonte codex|claude] [--desde AAAA-MM-DD]` busca em tudo o que já foi dito com o Codex e o Claude nesta máquina (índice reindexado de hora em hora) — use antes de perguntar ao usuário algo que pode já ter sido decidido.

Run with the 10/18/2026 kit; only the path of the rehearsal folder was shortened. The pytest time changes from machine to machine.

  • Folder outside a project: the script requires the project folder to exist. The hook and the vigia look for longrun/*/state.md at the root of the git repository.
  • Reusing the slug: two runs on the same day with the same slug collide and the script refuses. Use another slug; don't delete the old folder, it is history.
  • Writing "concluído" in state.md by mistake: for the hook and the vigia, the run is no longer active.
