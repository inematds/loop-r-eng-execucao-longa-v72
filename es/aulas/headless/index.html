Clase 6 · 20 min

Loop headless: loop-longrun.sh, flock, timeout y MemoryMax

En el /goal interactivo, quien decide que terminó es un evaluador que lee la conversación. En el loop headless, quien decide es la prueba, ejecutada por el propio loop, con los archivos de prueba protegidos. En esta lección ejecutas el loop-longrun.sh con un agente falso: ves cómo concluye, ves cómo se revierte la trampa y ves cómo la trava impide dos loops en la misma carpeta, sin gastar cuota.

Comenzar la clase

En esta clase vas a

  1. 1El loop.env: pruebas, protegidos, permitidos y topes
  2. 2flock, timeout y MemoryMax en cada ciclo
  3. 3Prueba protegida modificada = revertida y ciclo fallido
  4. 4systemd: vigila cada 10 min y cron con flock

Objetivo: ejecutar el loop-longrun.sh con un agente falso y ver cómo la prueba decide: concluido, trampa revertida, estancamiento y trava de segunda copia.

03 · Ensayo con agente falso

El loop acepta CODEX_BIN: si apuntas a un script, no se llama a ningún modelo. Es la forma barata de probar tu loop.env antes de gastar cuota.

ensaio-loop.sh · monta el proyecto de prueba
# ensaio-loop.sh — monta un proyecto de prueba con 3 pruebas congeladas y dos agentes FALSOS
E=/tmp/ensaio-loop; K=~/projetos/execucao-longa
rm -rf $E && mkdir -p $E/proj/tests && cd $E/proj
git init -q && git config user.name ensaio && git config user.email ensaio@local
cat > tests/test_conta.py <<'PY'
from conta import conta_palavras
def test_vazio(): assert conta_palavras("") == 0
def test_simples(): assert conta_palavras("um dois três") == 3
def test_espacos(): assert conta_palavras("  um   dois ") == 2
PY
printf 'def conta_palavras(texto):\n    raise NotImplementedError\n' > conta.py
printf '[pytest]\npythonpath = .\n' > pytest.ini
printf '__pycache__/\n' > .gitignore
git add -A && git commit -qm "base: testes congelados"
$K/tools/novo-longrun.sh $E/proj conta-palavras > /dev/null
D=$(ls -d $E/proj/longrun/*)
echo "Implementa conta_palavras en conta.py. Lee goal.md, state.md y plan.md antes. No toques tests/." > $D/prompt.md
cat > $D/loop.env <<'ENV'
TESTE_RAPIDO="python3 -m pytest -q"
TESTE_FINAL="python3 -m pytest -q"
PROTEGIDOS="tests/ pytest.ini"
PERMITIDOS="conta.py"
MAX_CICLOS=4
MIN_CICLO=2
MEM=1G
ESTAGNACAO=3
ENV
git add -A && git commit -qm "longrun: pasta da execução"
printf '#!/usr/bin/env bash\ncat > /dev/null\nprintf "def conta_palavras(texto):\\n    return len(texto.split())\\n" > conta.py\n' > $E/agente-bom.sh
printf '#!/usr/bin/env bash\ncat > /dev/null\nrm -f tests/test_conta.py\n' > $E/agente-trapaca.sh
printf '#!/usr/bin/env bash\ncat > /dev/null\nsleep 6\n' > $E/agente-lento.sh
chmod +x $E/agente-*.sh
echo "pronto: $D"
Terminal · las tres rondas

cd /tmp/ensaio-loop/proj && D=$(ls -d $PWD/longrun/*) && L=~/projetos/execucao-longa/tools/loop-longrun.sh

Las pruebas borradas por la trampa volvieron: el loop revirtió los tres ciclos y escribió tres líneas "revertido pelo loop" en failures.md.

Sin la línea __pycache__/ en el .gitignore, el propio pytest crea archivos nuevos dentro de tests/. El loop ve un archivo no rastreado en una carpeta protegida y cuenta el ciclo del agente BUENO como trampa. Capturado en el mismo ensayo, sin el .gitignore:

2026-10-19 03:56:28 ciclo 1: agente saiu rc=0 em 0s
2026-10-19 03:56:28 ciclo 1: agente mexeu em arquivo protegido → revertido, ciclo falho
2026-10-19 03:56:29 CONCLUÍDO no ciclo 1: teste final passou (3 passed)

Terminó porque la prueba final pasó, pero el ciclo quedó marcado como fallido y fue a failures.md. Con el agente lento, tres ciclos así llevarían a estancamiento. Antes de encender el loop: git status --short tests/ después de correr las pruebas tiene que salir vacío.

04 · Fuera de la terminal: systemd y cron

El loop corre solo; estas tres piezas lo cuidan.

1. Vigia

El vigia.py busca ejecuciones activas (state.md sin "concluído") y alerta una vez por cada problema: PARADO (el loop.log registró una parada), PARADO SEM AVISO (hay loop.log pero ningún proceso del loop vivo) y OCIOSA (nada cambió en la carpeta ni en las sesiones hace N minutos).

Alerta = línea en ~/.local/state/execucao-longa/alertas.log; notify-send solo con --desktop.

2. Ruta en las units

Las units en tools/systemd/ traen la ruta absoluta de la máquina del autor (/home/nmaldaner/…). Cámbiala por tu HOME antes de activar, o el timer se dispara y el servicio falla en silencio.

Verificasystemctl --user list-timers longrun-vigia.timer → muestra el próximo disparo

3. Cron con traba

Todo cron que llama a un agente lleva flock -n sobre un archivo de lock y timeout con tope. En claude -p, también --max-turns.

Sin flock, un disparo lento y el siguiente corren juntos en la misma carpeta.

Línea de crontab0 2 * * * flock -n /tmp/meu-loop.lock timeout 4h ~/projetos/execucao-longa/tools/loop-longrun.sh ~/projetos/[projeto]/longrun/[pasta]

05 · Activar el vigia (una vez por máquina, Linux)

Copia las units del kit, cambia la ruta por la tuya y activa el timer.

Terminal · vigia cada 10 min
mkdir -p ~/.config/systemd/user
cp ~/projetos/execucao-longa/tools/systemd/longrun-vigia.* ~/.config/systemd/user/
sed -i "s#/home/nmaldaner#$HOME#g" ~/.config/systemd/user/longrun-vigia.service
systemctl --user daemon-reload
systemctl --user enable --now longrun-vigia.timer
systemctl --user list-timers longrun-vigia.timer
python3 ~/projetos/execucao-longa/tools/vigia.py --seco   # una ronda a mano, sin guardar estado
